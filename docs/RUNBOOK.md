# 📘 راهنمای اجرای قدم‌به‌قدم (Runbook)

این سند برای کسی نوشته شده که فقط یک سرور Ubuntu و این پوشه را دارد. همه‌چیز
قدم‌به‌قدم، از صفر تا داشبورد بالا و بکاپ مجدول.

---

## قدم ۰ — پیش‌نیازها

- **سرور Ubuntu 22.04 یا بالاتر**، حداقل ۴ گیگ رم و ۴۰ گیگ فضای خالی
- دسترسی `sudo`
- یک دامنه (اختیاری برای آغاز — روی `localhost` هم کار می‌کند)

نصب‌کننده خودش Docker را اگر نباشد نصب می‌کند؛ کافی است ابتدا بررسی کنید:

```bash
sudo ./setup.sh --check
```

اگر هر سه خط ✔ سبز بود، یعنی همه‌چیز برای نصب آماده است.

---

## قدم ۱ — نصب (یک دستور)

```bash
sudo ./setup.sh
```

این دستور به ترتیب:

1. سیستم‌عامل، رم و فضای دیسک را اعتبارسنجی می‌کند
2. Docker و compose plugin را (در صورت نیاز) نصب می‌کند
3. فایل `.env` می‌سازد و **همهٔ سکرت‌ها را تصادفی تولید می‌کند**:
   `JWT_ACCESS_SECRET`، `JWT_REFRESH_SECRET`، `ENCRYPTION_MASTER_KEY`،
   `POSTGRES_PASSWORD` (و همان پسورد داخل `DATABASE_URL` سینک می‌شود)،
   و `OTP_HASH_PEPPER` (فقط اگر خالی باشد — تا OTPهای صادرشده خراب نشوند)
4. ایمیج‌ها را build و سرویس‌ها را بالا می‌آورد
5. میگریشن‌های دیتابیس را اجرا می‌کند
6. تا لحظه‌ای که `/api/health` پاسخ `ok` بدهد صبر می‌کند

در پایان آدرس داشبورد را چاپ می‌کند. اگر `.env` از قبل وجود داشته باشد،
هیچ‌کدام از سکرت‌ها **دوباره بازنویسی نمی‌شوند** (ایمن در برابر اجرای مجدد).

> ⏳ اولین اجرا (دانلود ایمیج‌ها) بسته به اینترنت ۵ تا ۱۵ دقیقه طول می‌کشد.

---

## قدم ۲ — ستاپ‌ویزارد (اولین ورود)

1. مرورگر را باز کنید: **http://localhost:8080**
2. چون هنوز مالکی ساخته نشده، **ویزارد راه‌اندازی خودکار بالا می‌آید**:
   - ساخت حساب مالک (شماره موبایل + نام)
   - ارسال OTP (در حالت dev، کد در لاگ container چاپ می‌شود:
     `docker compose logs api | grep -i otp`)
   - تایید OTP و ورود
3. در داشبورد، از بخش **تنظیمات**:
   - **پنل پیامک کاوه‌نگار** (`KAVENEGAR_API_KEY`) را اگر دارید وارد کنید —
     یعنی OTPهای واقعی با SMS بروند. بدون کلید، پیامک ماک سرو می‌شود (فیلد تست عالی).
   - **درگاه زرین‌پال** را اگر merchant-id دارید وارد کنید.
   - **پروایدر هوش‌مصنوعی**: مسیر `AI_PROVIDER_KEY` را با کلیک روی تنظیمات provider فعال کنید.
4. (اختیاری اما توصیه‌شده) برای نسخهٔ نهایی **پس‌کی/اثر انگشت** را هم در تنظیمات اکانت ثبت کنید —
   ورد اصلی پلتفرم پس‌کی است و OTP فقط مسیر بازیابی است.

---

## قدم ۳ — راستی‌آزمایی سلامت

```bash
./scripts/diagnostics.sh      # وضعیت همهٔ سرویس‌ها + اتصال DB
curl -s http://localhost:8080/api/health   # → {"status":"ok", ...}
```

## عملیات روزمره

| کار | دستور |
|---|---|
| روشن | `./scripts/start.sh` |
| خاموش | `./scripts/stop.sh` |
| به‌روزرسانی به کد جدید | `./scripts/update.sh` |
| لاگ زندهٔ API | `docker compose logs -f api` |
| بکاپ دستی | `./scripts/backup.sh` → خروجی در `backups/backup-*.tar.gz` |
| **بازیابی از بکاپ** | `./scripts/restore.sh --confirm backups/backup-XXXX.tar.gz` (به یک checksum-check و تأیید صریح نیاز دارد) |
| وضعیت | `./scripts/diagnostics.sh` |

### بکاپ مجدول (توصیه‌شده در فیلد)

```bash
sudo crontab -e
# هر شب ساعت ۰۳:۰۰ (به وقت سرور):
0 3 * * * /path/to/legal-platform/scripts/backup.sh >> /var/log/legal-backup.log 2>&1
```

بکاپ به‌صورت خودکار `provider_configs` را از داخل دیتابیس کنار می‌گذارد (سکرت‌های
پروایدر در DB رمز شده‌اند و نیازی به رفتن به فایل بکاپ ندارند).

### حوصله‌ی دیسک به‌طور خودکار
- `backup.sh` بعد از ساخت هر آرشیو، فایل‌های قدیمی‌تر از **`BACKUP_RETAIN_DAYS` (پیش‌فرض: ۳۰ روز)** را همراه با مانیفست‌شان پاک می‌کند. برای تغییر: `BACKUP_RETAIN_DAYS=14 ./scripts/backup.sh`.
- `diagnostics.sh` علاوه بر health، اگر جدیدترین بکاپ **بیش از ۷ روز** قدیمی باشد یا آرشیو آخر بازخوانی‌شدنی نباشد، FAIL می‌دهد — یعنی کرانِ روزانهٔ diagnostics در برابر «بکاپ بی‌صدا خراب شده» هشدار می‌دهد.

## عیب‌یابی سریع

| علامت | دلیل محتمل | چه کنم |
|---|---|---|
| `curl /api/health` → 503 با `AUTH_DEPENDENCY_DOWN` | پس‌گرس هنوز بالا نیامده | `docker compose ps`، چند ثانیه صبر، `docker compose logs postgres` |
| `docker: permission denied` | کاربر در گروه docker نیست | `sudo usermod -aG docker $USER` سپس logout/login |
| OTP نمی‌رسد | کلید کاوه‌نگار سِت نیست | در dev کد در لاگ است؛ برای فیلد کلید را در `.env` یا داشبورد قرار دهید |
| `port 8080 already in use` | سرویس دیگری روی ۸۰۸۰ | در `docker-compose.yml` پورت nginx را عوض کنید |
| باگ migration | هیچ‌وقت دست‌کاری نکنید | `docker compose logs api` را به توسعه‌دهنده بدهید |

## امنیت فیلد (پیش از real-usage)

1. `.env` را با دسترسی `chmod 600` نگه دارید و هرگز در git قرار ندهید.
2. `POSTGRES_PASSWORD` را فقط بعد از نصب ببینید اگر لازم است دیباگ کنید — و هرگز commit نکنید.
3. داشبورد ادمین را پشت فایروال/VPN محدود کنید، یا حداقل روی IP ثابت.
4. پس‌کی مالک را حداقل روی دو دستگاه ثبت کنید (بازیابی).
5. روزانه: `curl /api/health` cron + بکاپ شبانه + چک دستی یک‌بار بازیابی در هفته.
